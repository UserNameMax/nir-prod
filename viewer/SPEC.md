# Viewer — Спецификация

## Бизнес-ценность

Веб-интерфейс для аналитика тепловых сетей. Позволяет просматривать данные датчиков по объектам и датам, находить периоды с аномалиями показаний, управлять загрузкой архивов с данными.

**Пользователь:** аналитик, который работает с данными ежедневно — ищет объекты, смотрит графики, загружает новые архивы.

---

## Роль в системе

```
Аналитик ──браузер──▶ Viewer ──GET──▶  Data Service     (данные)
                              ──POST──▶ Ingestion Service (загрузка)
```

Viewer — frontend. Не хранит данные, не обрабатывает архивы. Только отображение и управление.

---

## Функциональные требования

### Навигация по объектам
- Список всех объектов с поиском по названию (debounce)
- Фильтрация по муниципалитету и типу котельной
- Переход к данным объекта

### Календарь
- Глобальный календарь: все дни, за которые есть хоть какие-то данные, и сколько объектов
- Объектный календарь: дни с данными для конкретного объекта
- Переход от дня в глобальном календаре → список объектов за этот день → данные объекта

### Визуализация датчиков
- 4 временных ряда за выбранный день: t_supply, t_return, p_supply, p_return
- Навигация между соседними днями с данными (← / →)
- Разрывы графика при отсутствии показаний (NaN)

### Управление загрузкой
- Загрузка одного или нескольких архивов одновременно (drag & drop)
- Прогресс в реальном времени: фаза парсинга и фаза записи
- История завершённых задач: дата, число записей, период данных
- Автовозобновление мониторинга после перезагрузки страницы

## Маршруты

| Путь | Страница | Описание |
|------|----------|----------|
| `/` | ObjectList | Список объектов с поиском и фильтрами |
| `/calendar` | GlobalCalendar | Глобальный календарь по всем объектам |
| `/calendar/:date` | DayObjects | Объекты с данными за конкретный день |
| `/object/:id` | ObjectCalendar | Календарь дней для объекта |
| `/object/:id/day/:date` | DayView | Графики датчиков за день |
| `/ingest` | IngestPage | Загрузка архивов и история задач |

### Флоу навигации

```
ObjectList → ObjectCalendar → DayView
GlobalCalendar → DayObjects → DayView
```

---

## Нефункциональные требования

| Параметр | Требование |
|----------|-----------|
| Отзывчивость | ключевые переходы < 1 сек |
| Полноэкранный календарь | без вертикального скрола страницы |
| SPA-роутинг | F5 на любом маршруте не даёт 404 |
| Polling прогресса | каждые 2 сек при активных задачах |

## Текущая реализация (reference)

**Стек:** React 18, TypeScript, Vite, Tailwind CSS v4, Recharts, React Router v6

### Страницы

**ObjectList** — таблица объектов, пагинация 100/стр, debounce 300ms, фильтры по municipality и facility_type.

**GlobalCalendar** — полноэкранный месячный грид (6×7 = 42 ячейки, `h-screen flex flex-col`). Синие дни = есть данные, тултип = количество объектов. Источник: `GET /sensors/calendar/summary`.

**DayObjects** — список объектов за день. Источник: `GET /sensors/calendar/objects?date=`. Клик → `/object/:id/day/:date`.

**ObjectCalendar** — метаданные объекта + месячный грид. Источник: `GET /sensors/calendar?object_id=`.

**DayView** — сетка 2×2 из графиков. Загрузка данных и календаря независимы (split loading): графики рендерятся сразу, навигация по дням — после. Список дат кешируется в `sessionStorage` по `object_id`.

| Датчик | Поле | Единица | Цвет |
|--------|------|---------|------|
| Температура подачи | `t_supply` | °C | красный |
| Температура обратная | `t_return` | °C | оранжевый |
| Давление подачи | `p_supply` | МПа | синий |
| Давление обратное | `p_return` | МПа | фиолетовый |

**IngestPage** — drag & drop загрузка. Активные задачи (queued/processing) — карточки с прогресс-баром (фаза 1: files_processed/files_total, фаза 2: merge_processed/merge_total). История — таблица done/error задач.

### API-клиенты

| Файл | Сервис | Методы |
|------|--------|--------|
| `api/dataService.ts` | data-service `:8000` | getObjects, getObject, getCalendar, getCalendarSummary, getObjectsByDay, getSensors |
| `api/ingestService.ts` | ingestion-service `:8001` | upload, getJob, listJobs |

URL через Vite env: `VITE_DATA_API_URL`, `VITE_INGEST_API_URL` (default: localhost).

### Сборка

Multi-stage Dockerfile: `node:20-alpine` (npm build) → `nginx:alpine` (serve dist). `try_files $uri /index.html` для SPA-роутинга. URL сервисов передаются через `build.args` в docker-compose.
